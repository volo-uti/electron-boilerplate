# AGENTS.md

Electron desktop app, one package: Electron Forge with Vite builds the main process, the preload and a React renderer. Process, layer and import rules are enforced by lint, not by convention.

## Commands

Run from the repo root. **`pnpm check` is the gate**: format check, lint (including process and layer boundaries), typecheck, locale parity, index freshness, unit tests, and a packaged build for this OS. Run it before declaring work done. Remote CI runs no tests: it only builds the Windows installer. `pnpm verify` runs the same check in a clean Docker container, and the `pre-push` hook uses it on `main` and `develop`.

| Command                                                                  | Purpose                                                                                          |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `pnpm install`                                                           | Install (run `nvm install` first; Node in `.nvmrc`, pnpm in `packageManager`)                    |
| `pnpm dev`                                                               | Run the app with the Vite dev server (renderer hot reload)                                       |
| `pnpm check`                                                             | The gate                                                                                         |
| `pnpm lint` · `pnpm fmt` · `pnpm typecheck` · `pnpm test` · `pnpm build` | Single steps (`build` packages the app into `out/`)                                              |
| `pnpm index`                                                             | Regenerate the shared-code index below (the gate fails when it is stale)                         |
| `pnpm e2e`                                                               | Build, then Playwright drives the app and runs axe (separate from the gate)                      |
| `pnpm verify`                                                            | `pnpm check` in a clean Docker container (needs Docker)                                          |
| `pnpm release`                                                           | Release from a Mac: gate, macOS and Linux installers, draft release, tag (see `docs/release.md`) |
| `pnpm update-check`                                                      | Outdated deps (Electron included), Node LTS, pnpm                                                |

## Structure

```
src/main/                    main process (Node): lifecycle, window, app:// protocol, IPC handlers
src/main/ipc/                one file per contract area; handle() checks the sender and the input
src/preload/                 sandboxed bridge: exposes the contract as window.api, nothing else
src/renderer/app/            entry, router and routes (composition root)
src/renderer/features/<f>/{domain,application,data,presentation}/
src/renderer/shared/         renderer config, providers, i18n, app-level ipc- adapters
src/renderer/ui/             atoms, molecules, organisms, templates, lib, styles/theme.css
src/renderer/messages/       {en,ko}.json
src/shared/                  process-neutral TypeScript: domain (result, errors), data (http client), ipc (contract), i18n
e2e/                         Playwright tests against the built app
scripts/                     init, release, update-check, verify, check-locales, agent-index
```

## Rules

- **Processes**: the renderer is sandboxed web code. It never imports `electron`, Node built-ins, `src/main` or `src/preload`. The preload imports only `electron` and `src/shared`. `src/shared` imports only `zod` and runs in every process. Separate tsconfigs give the renderer no Node types and the main process no DOM types.
- **IPC**: every call from the renderer to the main process is one channel in `src/shared/ipc/contract.ts` (a name, a zod input, an output). The preload exposes the contract as `window.api.<area>.<method>`, and its calls resolve to a `Result` and never reject. The main process registers each channel once with `handle()` in `src/main/ipc/<area>.ts`, which refuses senders outside the app and input that fails the schema. Never expose `ipcRenderer` or a generic `invoke`.
- **The main process holds no business rules**: it is the adapter to the OS (files, dialogs, native theme, ...). Use cases live in renderer features.
- **Layers** (inside one renderer feature): `presentation -> application -> domain <- data`. Presentation may also use domain types. `domain` imports no framework (only `zod`).
- **Features are isolated**: a feature never imports another feature. Routes in `src/renderer/app/` import features and wire them together.
- Lint (`eslint-plugin-boundaries`, written generically for `features/*`) fails the build on violations. Do not disable it; move the code instead.
- **Adapters**: data adapters are prefixed `http-` (real API), `mock-` (in-memory) or `ipc-` (the main process through `window.api`). `window.api` is read only in `ipc-` files (lint). Mock is the default for `http-` ports; `VITE_ADAPTER=http` switches. The route (composition root) picks the adapter and passes it down.
- **Expected failures are values**: return `Result` from `@shared/domain/result`; throw only for programmer errors. This holds across IPC: handlers return a `Result`.
- **Env**: renderer values are `VITE_*`, read only through `@renderer/shared/env`. Every value has a default, so the app runs with no env vars. A packaged app connects over https only (Content-Security-Policy); the default http `VITE_API_URL` works in `pnpm dev`.
- **Security defaults stay on**: `contextIsolation`, `sandbox`, no `nodeIntegration`, the `app://` protocol (never `file://`), the Content-Security-Policy in `src/main/trust.ts`, denied permissions, blocked navigation and new windows (web links open in the OS browser), the fuses in `forge.config.ts`. A feature that needs one opened says why in the change.
- **Versions live in `package.json`** (exact for `electron` and `typescript`), plus `.nvmrc` and `packageManager`. `node_modules` is flat (`nodeLinker: hoisted`, required by Forge), so lint fails an import of a package that is not in `package.json`.
- **Locale parity**: `src/renderer/messages/en.json` and `ko.json` keep identical key sets (`pnpm check:locales`). All UI strings go through use-intl.
- **Reuse before writing**: find the component in the index blocks of this file first. If the product depends on a UI package that has its own index block here, that package comes first: use its components and variants, and let `src/renderer/ui` only compose them or add what the package lacks. Do not rebuild a package component because one detail differs: try its props, then write only the missing detail by hand and mark it `// TODO(library: <what is missing>)` (say what you tried), and report the gap to the package's maintainers. `pnpm lint` lists the open markers as warnings.
- **Replacing raw elements**: when a new atom replaces a raw element, add it to the replacement map in `eslint.config.mjs`. A UI package that ships its own replacement map is spread into that map (one `no-restricted-syntax` rule keeps the env check too) and owns the replacements for its components.
- **Imports** use the aliases `@renderer/*` and `@shared/*` (`tsconfig.base.json`) across folders and relative paths inside one.
- **Config files** are `.ts` where the tool loads TypeScript without extra dependencies (`forge.config.ts`, `vite.*.config.ts`, `vitest.config.ts`, `playwright.config.ts`, `prettier.config.ts`), otherwise `.mjs` (`eslint.config.mjs`). No `.prettierrc`.
- **Design tokens** live in one file, `src/renderer/ui/styles/theme.css`.
- **Query keys** are `[domain, entity, params]`, e.g. `["billing", "invoice", { id }]`.
- File names are kebab-case and carry no role suffix (the folder is the role): `domain/user.ts`.
- Docs, code and comments are English.

## Starting a project

After cloning, run `scripts/init --name <name> --org <reverse-domain>` once. It names the package and the product, sets the app id to `<org>.<name>`, rewrites the README and starts a fresh git repository.
